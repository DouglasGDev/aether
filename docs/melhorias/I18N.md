# I18N — segunda passagem do maintainer sobre as chaves de idioma

Escopo: as chaves que o teste de paridade **não** alcança. A paridade
(`idiomas.rs`, `todos_os_idiomas_tem_exatamente_as_mesmas_chaves`) compara os
arquivos `locales/pt-BR.json` e `locales/en-US.json` entre si. Ela é cega para
dois casos, e os dois aparecem na tela como o caminho da chave, não como palavra:

1. uma chave montada em runtime que falta nos **dois** arquivos ao mesmo tempo;
2. uma chave que o código nunca escreve literal, só por `format!` ou template.

## O que mudei

- `src-tauri/src/idiomas.rs` — `pub fn tem_texto(chave: &str) -> bool`
  (:120, antes de `tr`): verdadeiro só quando **todo** catálogo embutido tem a
  chave. `tr` não serve para isso porque a referência cobre o buraco do idioma
  ativo; o que a tela mostra é o caminho cru só quando falta nos dois, e é
  exatamente esse o caso que a paridade deixa passar.
- `src-tauri/src/idiomas.rs` — `tem_texto_recusa_o_que_nao_foi_escrito_e_aceita_o_que_esta_la`
  (:136). Prova a própria guarda: recusa `bancada.caso.quem-nunca-foi-escrito`
  e aceita `idioma.nome`. Valide assim, e não apagando uma chave dos dois
  locales, porque seis agents estão rodando `cargo test` nesta árvore agora e
  uma edição temporária em `locales/` apareceria para eles como um vermelho
  meu.
- `src-tauri/src/bancada.rs` — `todo_caso_da_bancada_tem_nome_em_todo_idioma`
  (:1043, fim do módulo de testes): anda `CASOS` (:33, a mesma lista que a
  bancada executa e que a tela usa em `BancadaDialog.tsx:141`) e exige texto nos
  dois idiomas para cada `bancada.caso.{id}`. Um caso novo sem palavra falha
  aqui, não na tela do dono.

## Follow-up honesto

Uma chave de front montada em runtime (`geracao.${chave}`, `voz.aba${nome}`,
`bancos.op${Operacao}`, `modelos.${fase}`, `runtime.${fase}`, `bancada.caso.${id}`)
não tem guarda automatizada, porque não há runner de teste no front. Fechar isso
significa escolher: (a) um teste de vitest que acha as chaves a partir das
tabelas reais dos componentes, ou (b) um passo no `npm run build` que quebre se
alguma família não resolver. É decisão do maintainer — adiciona infra de teste
ao projeto, e por isso não foi feito às escondidas aqui.
